## [2026-10-05] 建包 v1.0

**改了什么**

- 新建技能包 `srt-cn-translate`，把一次完整的外文字幕翻译项目（全片 1990 条 cue）中跑通的
  全流程固化为可复用技能。
- `SKILL.md`：成品规范（三件套命名 / UTF-8 BOM ＋ CRLF / 中文全角标点 / 每 cue ≤2 行 /
  双语轨严格机械拼接）、标记处理口径（说话人前缀与 `[音效]` 原样留英文）、
  六步流程（体检 → 检索现成中字 → 校验时间轴 → 对齐参考 → 分批审校 → 组装 → 独立校验）、
  通用坑清单、质量基线。
- `scripts/srt_tools.py`：四个子命令 —— `probe`（体检）/ `align`（对齐参考译文并导出分批工作稿）/
  `assemble`（组装 zh-CN 与 zh-en）/ `verify`（独立校验成品）。纯标准库，无第三方依赖。

**为什么**

- 该流程已在实战中跑通并通过全部机械校验（cue 数 1990/1990、时间轴逐条一致、
  双语拼接 1990/1990 机械一致、正文半角标点 0、最长行 30 字）。
- 同类需求会反复出现；不沉淀则每次都要重新踩一遍同样的坑（SubHD 下载 403、
  参考字幕时间轴漂移、参考译文错译、双语轨拼接口径）。

**是否出错**

- 建包过程无错。
- 建包后发现一处**未闭环**（见「已知待办」第 1 条），已登记未处理。

**来源**

- 实战项目：影视字幕翻译 ——《Wrath of Man》(2021)，全片 **1990** 条 cue，
  片长 00:01:00 – 01:51:47。
- 规范样板：某剧院现场放映作品的三件套字幕（英文轨 / zh-CN / zh-en，**2864** 条），
  本包的格式规范即从其逐条实测提炼（三文件 cue 编号与时间轴完全一致、
  zh-en 逐字节等于「英文原文行 ＋ 中文行」）。
- 产出：`zh-CN.srt`（纯中文）＋ `zh-en.srt`（英中双语）。
